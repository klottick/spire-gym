# Act 1 continuation selectors: finite sites, local rules, and reachability limits

**Status: source-grounded continuation contract, with exceptional-history reachability still open.** This document makes selector obligations explicit for the standard fully-unlocked Ironclad A0 Act 1 under the selected native policies. It is not an implementation, source-parity timing contract, gameplay test, or whole-spec approval. Source facts below are bounded static findings from the pinned owned archive; native representation/ordering is a deliberate contract unless explicitly labelled source fact.

## 1. Evidence and rule vocabulary

The working archive SHA-256 is `cfad868ac8d65a88e71a0bf096fb09f78811e553effe0787c5309a655e081673`. No original game class, initializer, or runtime was executed. This contract relies principally on the accepted, bounded [Act 1 acquisition/continuation findings](2026-10-19-act1-continuations.md), especially §§2–7, and the selected policy in the consolidated Act 1 specification §§1.2/4. The continuation findings distinguish static facts from bytecode-checked dispatch branches; they do not establish initialized-history reachability for exceptional empty grids.

**Candidate identity** means the actual object instance in the owning domain, not a card ID substituted for an instance. **Offer order** is source-visible ordering; **selection order** is the sequence of player-picked instances. A native policy may use a canonical deterministic order where the selected RNG policy permits it, but may not expose hidden identities or change which objects qualify. “No choice” is a source branch only where stated; generic grid completion is never implied by an empty set. A `confirm` commits only the source-qualified result and never means “select first” by default.

## 2. Selector payload and completion contract

For each site below the continuation payload is the tuple `(site, parent-owner, phase, captured parameters, ordered candidate instance handles, required/maximum count, committed ordered result, result-consumer, resume checkpoint)`. The parent remains the run's current phase owner while a child is suspended. Candidate handles must be revalidated against the owning live collection at acceptance; stale handles reject without mutation/RNG advance. Commit is once-only. Results are consumed by the named source consumer, not by generic screen close. Closing/cancelling is not a universal return-to-map. The selected native contract retains these distinctions; exact serialization IDs belong to the native-schema owner.

Flags: `upTo` permits any count from zero through maximum; `any` means selection order does not affect the source result unless a row says otherwise; `cancel` is legal only where expressly marked; `zero` describes an actual zero-choice source route, not an empty-grid fallback. “Visible order” is the actual offered/list order; a hidden identity cannot be made a policy candidate before its legal reveal.

## 4. Commit, cancel, empty, and resume laws

1. Opening a selector captures its semantic parent, checkpoint, candidate instance identities and source parameters. Opening does not commit a choice, pay an uncommitted cancellable service, or regenerate the parent offer.
2. Selection order is retained when source callbacks operate per selected instance (notably multiple transforms/upgrades); do not sort away a source-visible order. Where source behavior is set-like, the selected native order is canonical and deterministic, and is explicitly distinct from visible candidate order.
3. Accept validates the complete selection against the still-live owner collection before any mutation. Invalid/stale submissions leave game state, rewards and RNG unchanged. One successful accept commits exactly once; duplicate confirmation cannot replay payment, removal, obtain or event callback.
4. Cancel is an available transition only at source-authorized cancel points. Shop purge browsing can cancel before a selected result; campfire grid cancellation returns to its menu. A mandatory post-commit selector (Purifier, Transmogrifier, Wing purge) cannot acquire a synthetic Leave/Cancel.
5. Empty branches are per-site: e.g. Living Wall/Cleric explicit no-grid routes; Astrolabe 0 transforms; Cage 0 differs from Cage 1–2; Pandora 0 opens no grid; generic fixed-count grids do not clamp/complete. A source branch that opens an empty mandatory grid remains precisely that fact until legal reachability or exclusion is established.
6. Child completion resumes the recorded source checkpoint only after that child's result consumer has committed. It does not prove all unrelated queued work is drained. Terminal arbitration, action scheduler and global causal settlement are owned by the execution specification, not this selector contract.

## 5. Exceptional histories: proven boundary and unresolved obligation

The pinned source establishes local predicates and branch behavior, but does **not** by itself establish that the exceptional entry states occur in a legal standard run. Accepted static findings explicitly require a legal history witness or exclusion for each committed empty mandatory grid, zero-removable-Cage, and Note's unremovable incoming/no-other-candidate case. No search miss, source-local accepted zero, guessed card-count, or invented empty initializer proves either side.

This document does not supply either proof and therefore claims neither reachability nor unreachability. No new product-policy question is yet justified; if a future proof establishes a reachable source softlock, main must route the exact history, source branch, absent successor, and policy options for user decision. No skip/default/administrative fault/gameplay defeat is proposed.

## 6. Evidence limits and handoff

Static source facts and native laws are separated above. No dynamic model, candidate-set checker, reachability search, or gameplay acceptance run is claimed here. The bounded continuation findings provide the exact locators and private evidence for the local source facts; future negative-control/model evidence must separately exercise candidate equality, order, cancel/empty distinctions, stale handles, double commit and witness constraints. Those consumers must join actual accepted revisions before claiming the cross-document interface complete.

The public card/room/event rules remain subject to whole-spec review and human approval. Future gameplay acceptance cases remain unexecuted; this specification makes no execution claim.
