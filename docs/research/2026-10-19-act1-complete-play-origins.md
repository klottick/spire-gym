## 1. Authority, fields, and boundary

This contract supplies the finite origins and captured values consumed by a semantic execution scheduler. It does not define the global causal frontier, action tie-breaking, terminal filtering, or selector internals; those are separate contracts. Native choices suspend rather than auto-select. A child selected from a generated/retained/copied card is a new card instance or an existing moved instance as its producer specifies; it never inherits an origin merely because its kind matches.

Use the following exact semantic records (field names are contract names, not wire IDs):

| Record | Fields and domains |
|---|---|

`energyOnUse` and `ignoreEnergyTotal` are queue fields. The card's later `ignoreEnergyOnUse` is a separately derived use field; it is never written back to queue provenance. The native consumer must preserve the source/destination receiver for every copy-side mutation. No codec IDs or byte layout are proposed here.

### Common dispatch law

For every queue row, enqueue does not admit a play. At manager dispatch, set `isInAutoplay = autoplayCard`, then run actual card `canUse` and source-specific hand predicates; only a successful gate proceeds. An earlier rejection has no normal `onPlay`/play-history commit, no payload, no ordinary payment, and follows that row's failed-entry cleanup. On accepted normal notifications, install queue capture, call the ordered manager `onPlay` chain (powers, relics, stance, blights, hand/discard/draw cards), and commit play history before the later dead/null/escaped-target test. If that later test fails, use and ordinary payment are omitted, history is not rolled back, and `UseCardAction` destination handling is not entered. The explicit suppressed-notification branch skips normal history/notification; it is not a permission bypass.

On a valid target, player use recalculates card damage, applies the source-specific X cap only when queue `ignoreEnergyTotal` is false, invokes card use, constructs the use action (constructor-time callbacks), notifies other cards, removes the instance from hand when applicable, and debits ordinary energy after those entry callbacks. Deferred payloads are not implicitly drained at this boundary. The use action later calls player then monster after-use powers. Purge and Power return early; otherwise destination precedence is purge, exhaust/Spoon handling, rebound/shuffle-back/return, then discard according to actual modifiers. A queue's `exhaustOnUse` request remains distinct from purge and the card's own exhaust flag. These are E19 bounded source facts; the selected native semantic model must preserve them without simulating animation frames.

## 3. X and payment submatrix

`energyOnUse` is a captured i32 input, not energy spent. For X cards, `-1` is the source sentinel that selects resolution-time live energy in the individual wrapper; `-2` unplayable is not X. Chemical X contributes +2 once inside each card action. Autoplay/free state can waive payment without forcing X to zero. The repeated/Omni capture is not Chemical X-adjusted: each child action applies its own modifier once.

| Card family at its resolution action | Effect amount | Exact payment guard and amount |
|---|---|---|
| Whirlwind, Skewer, Reinforced Body | Captured `energyOnUse` unless sentinel −1 then current energy; Chemical X +2; positive count gates their per-hit/per-Block payload | Positive count and captured `freeToPlayOnce=false` branches spend current live total (not captured amount); zero/nonpositive means no branch debit. |
| Malaise, Doppelganger, Tempest, Collect | Same captured/fallback + Chemical X; upgraded bonus +1 for the source-defined four upgraded actions | Positive adjusted count gates payload and nonfree live-total debit. Collect installs future upgraded Miracle duration rather than immediate cards. |
| Multi-Cast | Captured/fallback + Chemical X + upgraded increment, only with an orb present | Entire effect and payment requires current orb; no orb means neither payload nor payment. |
| Transmutation | `use` first raises capture to at least current energy; its action then applies sentinel fallback, Chemical X, positive generated count | Positive count and nonfree gate current-total payment. Output fresh-copy→optional upgrade→turn setter(0)→temporary creation; setter leaves X −1 fields intact, and a self-generated Transmutation receives no automatic new free flag. |
| Conjure Blade | Upgraded producer forwards capture+1; action falls back only when forwarded value is exactly −1, then Chemical X; creates Expunger even for zero count | Nonfree current-total payment is outside positive-count condition: even zero creates/pays under the action's nonfree branch. Ordinary fixed-cost debit and card-local X payment are separate checkpoints; never charge both. Five repeat powers use copied capture and explicit `true/true`; Omniscience uses `true/false` queue flags and later derives `ignoreEnergyOnUse=true` only after admission. This distinction is normative even though both autoplay routes normally avoid ordinary energy debit.

## 4. Hook, history, copy and destination invariants

1. Earlier `canUse` rejection ⇒ no ordinary accepted-play history. Accepted manager entry ⇒ notifications/history commit before later dead/null target validation. A late invalid target omits player use and ordinary payment and never rolls back history.
2. Notification suppression is a distinct manager branch. It must not be represented as admitted normal history with zero payload.
3. For an admitted child, ordinary callbacks are ordered manager notifications before use; `card.use` and `UseCardAction` construction happen before ordinary energy debit. Constructor callbacks are at use-entry, not when queued payload actions resolve.
4. After-use callbacks are player powers then monster powers. Purge/Power early return differs from ordinary destination logic. Havoc exhaust request, card inherent exhaust, Spoon, Omni purge, copy relation, and ordinary discard are independent inputs.
5. Selection, producer parent payment, and child play payment each have independent commit identities/checkpoints. Resumption resumes after selected-result commit; it never rebuilds a copy, recharges parent, rerolls captured energy, or repeats parent history.
6. Card-generated output being in hand is not a play; pile movement to hand is not a draw; retrieval is not construction; copying is not aliasing. Any actual later hand play gets a new `HAND.direct` origin.
7. Setup/Forethought positive-combat-cost free flag, Madness zero-cost mutation, Confusion clearing, reset, and use cleanup are distinct state writes. The guard failing does not clear a preexisting free flag.
8. Eviscerate's makeCopy may mutate the source; Blood for Blood's makeCopy mutates the returned fresh object; Searing Blow's count-taking constructor does not replay prior damage upgrades; stat-equivalent construction calls makeCopy first and then restores selected source fields. Record both source and destination before/after.
