# Act 1 native RNG and representative map contract

Date: 2026-10-19 · completion-v1 task `spire-gli.2.3.43`

**Engineering contract proposal for independent review.** This document closes the native RNG and representative map *written model* under the selected policies in the consolidated Act 1 specification. It is not product code, source parity, an original-game execution, a source-seed ensemble, or approval to implement. Source facts and native choices are marked separately. The canonical policies remain: independent reproducible native systems, unbiased intended-weight draws, retained ordinary eligibility/history/pity/guarantees, and deterministic reject/regenerate until every exposed map is valid and has at least one Elite. No failed map is patched.

The normative baseline is [the consolidated Act 1 specification](../superpowers/specs/2026-10-19-ironclad-a0-act1-consolidated-design.md), particularly §§1.2, 3, 10 and 12. Its E20, E25 and E26 content records provide source-informed eligible catalogs, quantities and conditional rules. Source evidence is bounded to the records named below; it does not establish exact original runtime behavior.

## 1. Versioned seed and stream contract

### 1.1 Run seed input and root bytes

`RunSeedRequest` is exactly one of:

* `Root32(bytes[32])`: caller-provided root bytes, copied byte-for-byte;
* `Seed64(u64)`: unsigned integer encoded as exactly eight big-endian bytes; or
* `Entropy32`: request to capture exactly32 system-entropy bytes after complete reset/batch preflight.

For `Seed64(n)`, `RunRoot32 = SHA256(ASCII("spire-lab/act1/seed/candidate1") || 00 || BE64(n))`. `Root32` is already the root and is not hashed. A supplied root, including all-zero bytes, is deterministic. For `Entropy32`, capture32 bytes exactly once only after whole-batch preflight; those bytes are RunRoot32 and must be retained for replay. Entropy failure is administrative initialization failure, never a replacement seed. Seed adapter IDs are exactly `spire-lab-act1-seed-sha256-candidate1` for Seed64, `spire-lab-act1-root32-candidate1` for Root32, and `spire-lab-act1-entropy32-candidate1` for captured entropy. Existing `spire-lab-env-seed-sha256-v1` and standalone combat-v1 seed paths remain unchanged; dispatch by adapter identity.

The RNG contract ID is `spire-lab-act1-rng-hmac-sha256-v1`; the three seed adapter IDs are listed above. These are new run identities. Existing `spire-lab-rng-hmac-sha256-v1`, combat snapshot2, combat reference/observation fingerprints, `spire-lab-env-seed-sha256-v1`, and pinned HMAC dependency remain unchanged. A future change to framing, key derivation, word sequence, draw consumption, or the frozen accepted site registry requires a new run RNG ID, not a silent combat-v1 mutation. The site registry is separately identified in §5; this document's Act2 row is an amendment to the still-unimplemented v1 proposal and must pass independent review and controller/main routing before it is treated as accepted or Act2Ready may pass.

### 1.2 Semantic stream key derivation

`NativeRngState` is the immutable tuple `(contract_id, partition, run_id, role_id, site_id, scope, key[32], next_word:u128)`. The logical cursor ranges `0..=2^64`; the endpoint is exhausted, so a u128 (or u64 plus explicit exhausted bit) is required. Drawable indices `0..2^64−1` still have u64 block/lane encodings. Key, cursor and all semantic IDs are hidden state and never policy-visible. Strings are exact printable non-space ASCII bytes `0x21..0x7e`, length 1..255. IDs are not normalized or inferred from slot/worker/order/address/token.

The allowed partition IDs are exactly `train`, `selection`, `final`, `test`. `run_id` is exactly the accepted native RunKey framing `a1:<32-lowercase-hex-stream-identity>:<canonical-unsigned-decimal-episode-ordinal>`; the stream identity is caller-owned pool identity, episode ordinal is checked u64 and assigned before dispatch. The entire string, including the literal `a1:` prefix, is the exact `run_id` ASCII field in the stream-derivation frame; there is no second bare-hex encoding or bridge. A reset/replacement increments the checked episode ordinal. Reuse of identical root, partition, run ID, role and scope intentionally reproduces the same streams. Duplicate live run keys reject before entropy, identity or RNG consumption.

The exact frame `F` is `BE32(field_count)` followed by, for each field, `BE32(byte_length)||ASCII(field)`. Fields are `(partition, run_id, role_id, site_id, scope_0, …)`. `key = HMAC-SHA256(RunRoot32, ASCII("spire-lab/act1/rng/v1/stream") || 00 || F)`. Counter block `j=floor(next_word/4)` is `HMAC-SHA256(key, ASCII("spire-lab/act1/rng/v1/block") || 00 || BE64(j))`; bytes 0..7, 8..15, 16..23, 24..31 are four consecutive big-endian u64 words. Lane is `next_word mod 4`. One word advances only that stream by one; inputs/states are values and are not mutated. At `next_word=2^64`, drawing faults with the exact state and no wrap/reuse. No cross-stream parent cursor exists.

The derivation is stable over batching, worker count and scheduling because identities precede dispatch and are semantic. Distinct role/site/scope tuples derive separate keys. This is an engineering pseudorandomness/isolation contract, not a proof of information-theoretic independence or cryptographic security. Actual semantic IDs in §3 govern the independence boundary; accidental cross-system source correlations are not recreated.

**RunKey framing known-answer vector (new run RNG only):** `RunRoot32=000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f`; fields are `("test", "a1:00000000000000000000000000000000:0", "run.map.draft", "map.topology", "act1", "0")`; derived key is `5c8754b4ae444a0fd9a24cf7645cd68896b7eb7e01cc0ec69759ef936d2e371d`; first raw word is `7d85bafa62cbb99d`. Replacing the RunKey field with the former bare-hex form changes the key. This internal encoding ruling is a proposal under whole-spec review, not a new source fact or human-approved codec/fingerprint. The vector binds the proposed new-run field bytes only; it does not alter any standalone combat-v1 identity or pin.

### 1.3 State transitions and exact draw kernels

Every public operation validates its complete arguments and checked arithmetic before drawing. Invalid bounds, negative weights, empty support, malformed state/ID, or overflow consume nothing. Empty weighted candidate sets are a site-specific administrative content fault, never modulo-zero, skip, defeat, fallback or retry. A valid one-outcome draw has no entropy need and consumes no word.

* `word(S)`: emit next u64, return `S.next_word+1`.
* `below(S,b)`, `1≤b≤2^64`: if `b=1`, return 0 without draw. Otherwise `L=2^64−(2^64 mod b)`. Draw u64 `x` until `x<L`, return `x mod b`. Every rejected word advances this stream, nowhere else. No numerical retry cap; exhaustion is administrative fault with latest state.
* `integer_inclusive(S,lo,hi)`: `lo,hi` are exact signed i64 values with `lo≤hi`; checked u128 width `b=hi−lo+1≤2^64`; return `lo+below(b)` as i64. Any width overflow rejects without draw. It differs from half-open APIs by one endpoint.
* `bernoulli(S,numerator,denominator)`: exact u64 rational with `denominator∈[1,2^64]` and `0≤numerator≤denominator`; endpoints return false/true without drawing; otherwise return `below(denominator)<numerator`. A source binary32 threshold is represented by its actual finite integer-grid numerator and denominator, never a host float comparison.
* `weighted(S,[(id,w)…])`: input order is a required canonical semantic order; IDs are unique; each `w` is exact u64 and checked u128 sum `W` is in `1..=2^64`. Draw `r=below(W)`; choose the first row whose checked cumulative sum is strictly greater than `r`. Zero weights never win. Rejections consume only this stream. Validate all rows before drawing.
* `shuffle(S,items)`: detached shallow copy, descending Fisher–Yates for `i=n−1…1`, choose `j=below(i+1)`, swap `i,j`. Length 0/1 consumes nothing. Every ordering of distinguishable input positions has probability `1/n!`; equal IDs/objects aggregate their positional fibers, not a different sampler. Input sequence and instance identities remain unchanged.
* `sample_without_replacement(S, ordered_candidates, k)`: repeatedly use weighted selection over the current remaining rows and remove the selected row before the next selection. Validate `0≤k≤number of positive-weight rows` and all weights first. If weight is defined by a source rule, recompute it at the stated selection checkpoint; do not replace sequential conditional laws with a uniform subset.

For all operations, a mid-operation exhaustion/error returns no partial semantic result, but diagnostic state records the last consumed cursor. The pool faults/quiesces after dispatch, retains already committed gameplay effects, and emits no successful final, fabricated loss, rollback, reset, or retry. Invalid action/reset/batch inputs are rejected before dispatch and advance no RNG/state/token/ordinal/history.

### 2.1 Shared state, exact selection checkpoints, and replay visibility

Each draw request is `(site_id, source_owner_id, input_ordered_candidates, integer_weights, exclusions, history_snapshot, selection_ordinal, stream_role/scope)`. Candidate IDs are stable canonical UTF-8/ASCII content keys sorted by unsigned byte order unless a source mechanic specifies a meaningful ordered list (e.g. deck instance encounter order, ordered selection, event branch order). The caller supplies the actual candidate set and weights; no hidden generic “pool” resolver is permitted. A site registry row names both its content owner and its concrete state fields read/written.

For same-offer distinctness, append a selected ID to that offer's used-ID set immediately after accepted identity selection; retries filter that set only. For cards, update pity once after the rarity outcome and before identity rejection; taking/skipping does not undo offer-generation history. For relic/potion pool depletion, consume at the source selection checkpoint even if the offer is skipped, unless that exact consumer specifies otherwise. For event/card/potion output, offer generation, claim, obtain, insertion, hooks, and transition commit are separate state mutations. Invalid state/input faults before RNG. A rejected proposal consumes that site's draws; it does not restore cursors/history unless the source law explicitly uses a whole-proposal retry. Whole-proposal shop type rejection reruns rarity and identity; fixed-rarity card rejection reruns identity only.

Card reward rarity/identity bindings are caller-qualified, not one shared generic site: ordinary monster room, elite room, boss room, colorless reward helper, Prayer Wheel second offer, Dream Catcher Rest offer, each of the four Orrery offers, the fifth screen auto-card row, Neow-discarded auto-card row, and Tiny House's context-specific reward screen each has a distinct `card.reward.<caller>.rarity` and `.identity` site. All consume the same current ordinary card-pity state where the source helper does; caller differences (boss forced rare, colorless strict-0.3 helper, Rest/ordinary rules, excluded contexts) remain in the caller's weights/parameters. No stream key is shared solely because pity is shared.

Potion appearance/identity bindings are also caller-qualified: combat drop, merchant initial/restock, Courier replacement, Lab, Woman in Blue, Neow, Cauldron, Tiny House, combat Entropic Brew, outside-combat Entropic Brew, and Alchemize each uses its named source law. Prices are not a random site: shop card/relic/potion prices and purge price are deterministic E26 binary32/rounding expressions at their stated evaluation checkpoints; discount/reprice and paid-purge history are separate non-RNG state transitions.

`ReplayRecord` stores exact contract/seed adapter IDs, seed kind and original argument or Root32, derived RunRoot32, partition, pool/run semantic IDs, rules/content/site/RNG descriptor identities, complete `NativeRngState` values needed to reconstruct current private state, deterministic map draft ordinal, and accepted semantic decision sequence. A checkpoint stores all role/site stream keys and next-word counters (or a canonical derivation tuple plus counters); a counter without identity/root is insufficient. Replay is from-start: rebuild state using ordinary initialization, regenerate menus/maps and check each semantic candidate before applying it. No restoration from arbitrary mutable snapshot and no policy action sees replay attachment. Rejected map draft counts, raw words, keys, seeds, stream states and pity/rejection traces remain private; only final map facts legally revealed by gameplay can enter the observation. Read, batching, and worker scheduling consume no gameplay draw.

## 4. Representative native Act1/Act2 map generator

### 4.1 Inputs and domains

### 4.2 Draft topology (deliberate native algorithm)

1. Draw six distinct starting columns without replacement from ordered `[0,1,2,3,4,5,6]`; sort the selected starts ascending and assign them route labels0..5. Each route starts at `(x,0)`. Sorting is deterministic and consumes no entropy.
2. For each transition `y=0..13`, process routes in label order. Its legal raw candidates are `x'∈{x−1,x,x+1}∩[0,6]`, ordered ascending. Remove candidates that would cross any already-selected route edge for this same transition: for every earlier route `p`, require `(x−x_p)*(x'−x'_p)≥0`. Choose uniformly among survivors using `map.topology` scoped by `(act,draft_ordinal,y,route_label)`. If a route's legal set is unexpectedly empty, fail the draft administratively (do not invent fallback); under the ordered adjacent construction it is nonempty.
3. Add directed edge `(x,y)→(x',y+1)` for each ordinary transition. Multiple routes may share a node/edge; a node is one coordinate and duplicate edges are stored once. Its ordered parent-route occurrences are kept only in private generator state; graph parent/child sets are unique node references. Because each route advances one row at a time, all present nodes are reachable from a row-0 start and can reach row14. Add terminal boss-fan-in edges from every distinct row14 node `(x,14)` to boss `(3,15)`; these terminal edges are an explicit exception to ordinary horizontal adjacency.
4. Require row0 has exactly the six selected starts, every route has one node per y0..14, every ordinary edge advances exactly one row with `|dx|≤1`, ordinary edges never cross, all node coordinates are unique, every ordinary node is reachable from a row-0 start and can reach the boss through directed edges, and no edge points outside grid/boss. Each distinct row14 node has exactly one terminal edge `(x,14)→(3,15)`; terminal fan-in edges are not subject to `|dx|≤1` or ordinary-edge crossing checks. Require at least one interior merge (`indegree≥2`, `1≤y≤14`) and one interior branch (`outdegree≥2`, `0≤y≤13`); a draft lacking either is invalid, not repaired. Duplicate routes and merges are legal; disconnected/orphan nodes are not generated.

This is not a source topology replica: it deliberately uses six independent bounded choices under noncrossing constraints and does not claim matching source branching frequency, path topology, widths, or seed image. It is representative of source six-path, 15-row, seven-column, merge/branch/reachability structure.

### 4.3 Room counts and constrained assignment

Let `N` be the number of active nodes on rows other than 13; let `U` be the number of all active nodes after excluding fixed room nodes (row13 remains in U). For Act1, compute integer quotas with round-half-up `qS=round(5N/100)`, `qR=round(12N/100)`, `qE=round(8N/100)`, `qQ=round(22N/100)`; set `qM=U−qS−qR−qE−qQ`. Negative remainder is invalid draft. For the familiar full-width active row pattern, native quotas are derived from actual graph, not hard-coded counts.

Create qS Shop, qR Rest, qE Elite, qQ Event tokens in that order, then append Monster tokens until bucket length is U. Uniformly shuffle token positions with `map.room_bucket` `(act,draft_ordinal)`. Visit active untyped nodes in row-major `(y,x)` order. At each node scan bucket from front for first legal token and remove that token; if none, leave the node untyped until after the scan. The native legality predicate is:

* Parent exclusion is type-specific: reject Rest, Treasure, Shop, or Elite when an immediate parent already has that type. Do not apply this parent exclusion to Monster or Event.
* Sibling exclusion is type-specific: reject Rest, Monster, Event, Elite, or Shop when an already assigned sibling child of any immediate parent has that type. Do not apply this sibling exclusion to Treasure.

After every active node is visited, fill remaining nulls deterministically as Monster, in row-major order. A token that was never accepted remains unused and does not cause a second assignment pass. The `qE` tokens are guaranteed by the basket but the topology/ordinary legality rules can underfill; any final draft with zero assigned Elite is rejected (never fill an Elite, change the bucket, or patch a node). Room assignment deliberately retains source's category bucket, row-major first-legal scan, source-informed ordinary row domains and per-type parent/sibling exclusions, delayed null fill, and possible underfill shape while using native exact rational quotas/biased-free shuffle.
