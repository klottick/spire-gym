# Spire Gym 1.2.1

Version 1.2.1 fixes Giant Head’s Slow and high-energy gains in the shared
combat engine. It also exposes typed details for four engine bounds.

## Gameplay fixes

- **Giant Head’s Slow.** Completed card plays add stacks beyond 999, up to the
  signed 32-bit maximum of 2,147,483,647. Normal damage uses the original
  single-precision multiplier and signed 32-bit conversion. Slow resets at
  the end of the round.
- **Energy gains.** Legal gains at high energy now succeed and clamp live
  energy to 999, as in the original game.

## Typed engine bounds

The existing Python `RunFaultError` exposes a `bound` dictionary on applicable
faults. The same dictionary appears in `fault_cause()` and applicable batch
slot reports. PublicSearch exposes only the bound values in single and bulk
fault reports. The fields identify the counter, its limit and the attempted value.

| Counter | Limit |
| --- | ---: |
| Slow stacks (`slow`) | 2,147,483,647 |
| Cards in one generation request (`generated_card_request`) | 999 |
| Combat cards issued, including the starting deck and previously issued cards (`issued_combat_cards`) | 999 |
| Numeric combat card identity (`combat_card_identity`) | 18,446,744,073,709,551,615 |

A bound hit during resolution is a committed fault. See
[engine bounds](../standard-run-api.md#engine-bounds) and
[batch fault reports](../batching.md#engine-bound-faults).

## Verification

The post-merge extension build at `554e7a8` reproduced the 60 known failures in
the full Python suite, all in the legacy comparator at
`tests/python/combat/test_rust_differential.py`. Frozen fingerprints and replay
digests were unchanged. These results apply to that build.

## Verify a wheel

1. Import the extension from the target environment and record
   `spire_lab._native.__file__` and `spire_lab._native.build_info()`.
2. Check that `dirty` is `false`, `features` is `["spire-python/extension"]` and
   `profile` is `release`. Match `source_digest` and `file_digest` to the
   values published with the release.
3. Verify the wheel and `.so` SHA-256 values published with the GitHub release.

The wheel is distributed through GitHub Releases.

## Known differences and limits

- **Other reachable engine bounds.** Follow-up work will add typed details
  for remaining guards, including power and damage arithmetic, maximum HP
  and permanent Run resource limits.
- **Omniscience.** The original appends both selected-card plays behind
  waiting cards. The engine puts each play ahead of waiting cards and
  schedules the second after an eligibility check. This can change play
  order when other cards are queued, such as during Distilled Chaos.
- **Storm.** The original queues Lightning before the played Power’s cleanup.
  The engine can finish the Power before channeling Lightning.
- **PublicRoot refusals.** Public roots and branches still refuse draw
  knowledge beyond supported exact cases, hidden intents from Runic Dome,
  randomly targeted autoplay and its repeats (Havoc, Mayhem, Distilled Chaos
  and Omniscience), and picks among identical draw-pile copies in cases
  involving two-pick Seek+, Frozen Eye, non-exchangeable copies or mixed
  published copies.

Earlier limits remain documented in the [1.2.0 release notes](v1.2.0.md) and
[delivery limits](../delivery.md#7-known-limits-by-surface).
