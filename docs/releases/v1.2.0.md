# Spire Gym 1.2.0

Version 1.2.0 adds a public descriptor for combat-entry resources, an opt-in
compact layout for standalone combat, wider coverage of public search roots and
one gameplay fix to the card queue. Defaults are unchanged: the dense
observation is still the default, and every frozen fingerprint and replay digest
matches 1.1.1. The gameplay fix changes the rules IDs, so records made with
1.1.1 rules no longer replay. Rust is still the only simulator.

## What is new

- **Combat-entry resource descriptor (M39a).** `spire_env::combat_entry_resources_descriptor()`
  and, in Python, `spire_lab.combat_entry_resources.load()` publish a versioned
  descriptor of what an owned Standard combat entry may carry: relic and potion
  admission, counter and companion rules, potion-slot counts and bounds. Input
  errors from combat catalog decoding now name the field or resource class that
  was rejected, such as `gold`, `hp`, `max_hp`, `deck`, `relics`,
  `relic_counters`, `potions` or `burning`. Which inputs are admitted is
  unchanged. See [entry resources](../combat-entry-resources.md).
- **Compact standalone combat view (M39b, opt-in).** Standalone Standard combat
  sessions and batches, and public-search branch views, can use the new layout
  `spire-gym-standard-combat-view-compact-v1`. Pass `observation="compact"` to
  select the `standard-combat-compact-v1` preset, or add
  `capacity_preset="standard-combat-compact-play-v1"` for smaller arrays. Both
  presets accept capacity overrides and report overflow as a typed fault. The
  dense view stays the default. See the
  [Standard combat API](../standard-run-api.md#compact-standard-combat-view-m39b).
- **Wider public roots (M40a).** More positions can now be turned into a
  `PublicRoot` and searched from. A nested card play or queued repeat whose enemy
  target the player chose (a repeat from Double Tap, Duplication, Burst, Amplify,
  Echo Form or Necronomicon of a hand play) is now a supported root. A branch step
  that picks among identical, unpublished draw-pile copies of a single-pick grid
  (Secret Weapon, Secret Technique, Omniscience, Seek) now removes the chosen
  copy instead of refusing with `HIDDEN_ORDER_PICK`, where the draw knowledge is
  exact for that class. No gameplay, layout, rules ID or pin changes.
- **Developer tooling.** The `dev` dependency group adds pytest-xdist 3.8.0 (with
  execnet 2.1.2), so the full Python suite can run across workers; see
  [development](../development.md#full-python-suite-in-parallel). The
  `a20_checks` example adds `step_limit_episodes` to its JSON and prints a
  line to stderr, with character, ascension, seed and step count, for each
  single-session episode that reaches the 20,000-action limit. Diagnostic only.

## Gameplay fix: card-queue order (spire-d4h)

The shared combat queue now orders copies and top-card plays as the original
does. Copies made when a card is played go ahead of cards already queued.
Havoc, Mayhem and Distilled Chaos append the cards they reveal in order. A copy
of Havoc plays before the cards that it and its original reveal. A card now
finishes its ordinary cleanup before the next queued card plays, so a Havoc copy
can reshuffle the finished original when the deck runs out, a card played by
Havoc can draw the original from discard, and a finished Blood for Blood in
discard can receive its cost reduction. When several copy sources fire on the
same use, Player powers enqueue in list order, then Necronomicon enqueues its
copy, which plays first. Storm's Lightning resolves before those copies.

Effects on play: selection boundaries can move, Havoc can roll its next random
target at a different time, and downstream gameplay can differ from 1.1.1. During
a Distilled Chaos burst, an already queued potion card can be Time Warp's twelfth
play, and the queued cards left over retire unused. The Havoc card-order
difference that 1.1.1 listed as open is closed by this fix.

## Identities and compatibility

| Profile | 1.1.1 rules ID | 1.2.0 rules ID |
| --- | --- | --- |
| Standard | `spire-gym-native-standard-rules-v6` | `spire-gym-native-standard-rules-v7` |
| M10 Heart and Gym66 | `spire-gym-native-m10-rules-v3` | `spire-gym-native-m10-rules-v4` |
| M9 | `spire-gym-native-m9-rules-v4` | `spire-gym-native-m9-rules-v5` |

Records with an older rules ID fail closed with an explicit error; there is no
multi-version replay. Combat-v1 has no rules ID. Observation, action and
descriptor layouts are unchanged, no Python names are removed, and the
`build_info()` keys are unchanged.

**Re-pin and upgrade notes.**

- Move rules-ID pins to the values above; regenerate any stored records.
- Fingerprint pins stay as they are (list below).
- One Heart pin changed: the Watcher A0 supplied Heart digest, because Omniscience
  now exhausts before the card it plays. Five boundaries report the corrected
  exhaust order. The route keeps its actions, rewards and HeartVictory. The other
  Heart pins, the frozen replay digests and the agreement digests match their
  1.1.1 values.
- `source_digest` and `file_digest` of any extension build change, because the
  version bump and the dev dependency change `Cargo.toml`, `Cargo.lock` and
  `pyproject.toml`, which are digest inputs. 1.1.1 values do not carry over.

## Verify a wheel

1. Import the extension from the target environment and record
   `spire_lab._native.__file__` and `spire_lab._native.build_info()`.
2. Check that `dirty` is `false`, `features` is `["spire-python/extension"]` and
   `profile` is `release`. Then check that `source_digest` and `file_digest`
   match the values published with this release.
3. Check the wheel and `.so` SHA-256 values published with the release, then
   update consumer pins. Rules-ID pins must move; fingerprint pins stay.

The digests and artifact hashes are published with the GitHub release, not in
this file. There is no PyPI release.

## Known differences and limits

- **Omniscience (open).** The original appends both selected-card plays behind
  the cards already waiting. The engine inserts each play ahead of waiting cards
  and schedules the second only after the first passes its eligibility check.
  With other cards queued, such as during Distilled Chaos, this can change which
  card plays next.
- **Storm (open).** The original queues Lightning before the played Power's
  cleanup action. The engine can run the Power's finish checkpoint before the
  channel.
- **Public roots still refused.** `PublicRoot` and branch construction still
  refuses: draw knowledge beyond the exact cases, hidden intents (Runic Dome),
  randomly targeted autoplay (Havoc, Mayhem, Distilled Chaos, Omniscience) and
  its repeats, and picks among identical draw-pile copies for two-pick Seek+,
  Frozen Eye, non-exchangeable copies and mixed published copies.

The 1.1.1, 1.1.0 and 1.0.0 limits still apply. See
[delivery limits](../delivery.md#7-known-limits-by-surface).
