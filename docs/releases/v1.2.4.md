# Spire Gym 1.2.4

Version 1.2.4 adds native batched playouts for Standard public search. Search
callers can advance sampled combat branches under a declared public move rule
in one call to the native worker pool.

## Native batched playouts (PR #129, spire-n6b)

Rust and the Python native binding expose `playout_many` and `playout_action`
on their public search types. The Python facade exposes
`PublicSearch.playout_many` and `PublicBranch.playout_action`. Rust's
`PublicSearch::enemy_capacity()` gives the width of the enemy rows.

The `spire-gym-public-playout-v1` rule picks uniformly from legal actions
after filtering out excluded verbs. The default excludes `end_turn` and
`discard_potion`. If filtering leaves no actions, the rule picks uniformly
from all legal actions. Each pick uses a research key derived from the
branch's sample key, the playout seed and its accepted-action count. On the same
root, branches with the same `(research_seed, k)` share common random numbers
at equal step counts and playout seeds. Results are reproducible across worker
counts and batch groupings.

Playouts use the same Mask transition as one-action-at-a-time stepping with
`playout_action` and `step`. Preflight enforces `max_steps_per_branch` and
`max_total_steps` with the same budget accounting and fault isolation as
`step_many`. A fault preserves the accepted prefix and freezes only its branch.
A refusal leaves the token unchanged and the branch live, with no action applied
or retried. Refusal codes are `HIDDEN_ORDER_PICK` and `NO_LEGAL_ACTION`.

A finished Rust branch returns `token`, `reward`, `terminated`, `truncated`,
`end_reason`, `refusal`, `steps`, `branch_steps` and `summary`. End reasons are
`victory`, `death`, `escaped`, `step_limit` (truncated), `max_steps` (per-call cap
with the branch still live) and `refused`. The Python batch returns
`rule_id`, `tokens`, `rewards`, `terminated`, `truncated`, `steps`,
`branch_steps`, `end_reason`, `refusal`, `player_hp`, `player_max_hp`,
`enemy_hp`, `enemy_max_hp`, `enemy_present` and `fault`. Python adds
`fault` as an end reason and the facade includes `_refusal` and `_fault` masks.

In A20 standalone starts and a Standard Run's first combat, native playouts
were about 4.4–4.8× as fast as a `step_many` loop using the compact full view
at each step, and 5.6–6.3× as fast with the dense full view at one worker.
Speedups across both views were about 11–16× at four workers. The post-merge
build also measured roughly 10–18% more slot-steps per second for existing
stepping. See the [native playout API and benchmark](../standard-run-api.md#native-playouts-m41)
and the [Python example](../../examples/public_playout.py).

## Fear No Evil regression test (PR #130, spire-in0)

The test confirms the order already matches the original game. Fear No Evil
reads the target's intent before the hit, then resolves the hit and its
on-damage effects before entering Calm. Gameplay is unchanged.

## Identities and compatibility

Version 1.2.4 is an additive, drop-in upgrade from 1.2.3. Existing records
can be reused as-is. Observation, action, descriptor and root layouts, frozen
fingerprints, frozen replay digests, Heart pins and existing root digests
are unchanged. Rules IDs and `build_info()` keys stay at their current versions.

| Profile | Rules ID |
| --- | --- |
| Standard | `spire-gym-native-standard-rules-v9` |
| M10 Heart and Gym66 | `spire-gym-native-m10-rules-v6` |
| M9 | `spire-gym-native-m9-rules-v7` |

The version bump changes the extension's `source_digest` and `file_digest`
inputs. See the [1.2.2 fingerprint table](v1.2.2.md#current-frozen-and-compact-fingerprints)
for the unchanged pins.

## Verification

The post-merge extension build at `be24b80` passed all checks against the
existing baseline. The full `tests/python` run reproduced 60 known failures,
all in `tests/python/combat/test_rust_differential.py`. Fingerprints, rules IDs
and frozen replays matched the existing pins. These results apply to that build.

## Verify a wheel

1. Import the extension from the target environment and record
   `spire_lab._native.__file__` and `spire_lab._native.build_info()`.
2. Check that `dirty` is `false`, `features` is `["spire-python/extension"]`
   and `profile` is `release`. Match `source_digest` and `file_digest` to
   the values published with the release.
3. Verify the wheel and `.so` SHA-256 values published with the GitHub release.

The wheel is distributed through GitHub Releases.

## Known differences and limits

The limits from 1.2.3 carry forward, including public-search refusals under
Runic Dome when the public record cannot reconstruct a pending move or when
revealed information prevents a supported sample. Unpublished purge
dispositions, random-target autoplay and some choices among identical
draw-pile copies still limit search coverage. The Omniscience and Storm queue
ordering differences also remain. See the
[1.2.3 known differences and limits](v1.2.3.md#known-differences-and-limits)
and [delivery limits](../delivery.md#7-known-limits-by-surface).
