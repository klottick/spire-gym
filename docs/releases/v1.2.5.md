# Spire Gym 1.2.5

Version 1.2.5 adds a second native playout rule that keeps potions out of
sampled playouts, and adds gold and held potions to each playout summary.
Search callers can then value a branch by the resources it keeps.

## Tiered-verb playout rule (PR #132, spire-9wa)

The new rule `tiered_verbs` (`spire-gym-public-playout-tiered-v1`) sits beside
`uniform_exclude_verbs` (`spire-gym-public-playout-v1`). It takes two disjoint
verb sets:

- `never_verbs` (default `use_potion` and `discard_potion`): chosen only when
  no other action is legal.
- `last_resort_verbs` (default `end_turn`): chosen only when nothing outside
  both sets is legal.

Each pick is uniform among the legal actions outside both sets. If there are
none, it is uniform among the last-resort actions, and then among all legal
actions. The rule reads only the verbs in the legal table and the research
playout stream. It uses the same per-step research key as
`spire-gym-public-playout-v1`. When only one action is eligible, the rule
takes it without drawing, and later steps are unaffected. Stepping one action
at a time with `playout_action` and `step` gives the same trajectories and
results as `playout_many`.

In Python, `playout_many` and `playout_action` accept `rule="tiered_verbs"`
with optional `never_verbs` and `last_resort_verbs`. Pass `None` to use a
default and `()` for an empty set. These keywords cannot be combined with
`exclude_verbs`. A verb in both sets, an unknown verb or `padding` is rejected
without effect.

## Playout summary fields

Every playout summary now includes the player's gold and the potion in each
slot. Python results add `player_gold` (`uint32`), `potion_kind` (`int32`,
Standard `potion` vocabulary ids) and `potion_present` (`int8`). Rust adds
`PlayoutSummary::player_gold`, `PlayoutSummary::potions` and
`PublicSearch::potion_capacity()`. These values equal the public observation
at the end of the branch. A terminal branch's `player_hp` is HP after combat
cleanup. That guarantee is documented and tested.

Branches without potions play at about the same speed under either rule. With
potions held, `tiered_verbs` keeps them, so fights last longer. See the
[native playout API and benchmark](../standard-run-api.md#native-playouts-m41)
and the [Python example](../../examples/public_playout.py).

Per-branch changes to permanent cards (for example, Ritual Dagger growth) are
not reported yet.

## Identities and compatibility

Version 1.2.5 is an additive, drop-in upgrade from 1.2.4. Existing records
can be reused as-is. The existing rule, its id, its defaults and its results
are unchanged. Observation, action, descriptor and root layouts, frozen
fingerprints, frozen replay digests, Heart pins and existing root digests are
also unchanged. Rules IDs and `build_info()` keys stay at their current
versions.

| Profile | Rules ID |
| --- | --- |
| Standard | `spire-gym-native-standard-rules-v9` |
| M10 Heart and Gym66 | `spire-gym-native-m10-rules-v6` |
| M9 | `spire-gym-native-m9-rules-v7` |

The version bump changes the extension's `source_digest` and `file_digest`
inputs. See the [1.2.2 fingerprint table](v1.2.2.md#current-frozen-and-compact-fingerprints)
for the unchanged pins.

## Verification

The post-merge extension build at `673887a` passed all checks against the
existing baseline. The full `tests/python` run reproduced 60 known failures,
all in `tests/python/combat/test_rust_differential.py`. Fingerprints, rules IDs
and frozen replays matched the existing pins. These results apply to that build.

## Verify a wheel

1. Import the extension from the target environment and record
   `spire_lab._native.__file__` and `spire_lab._native.build_info()`.
2. Check that `dirty` is `false`, `features` is `["spire-python/extension"]`
   and `profile` is `release`. Match `source_digest` and `file_digest` to
   the values published with the release.
3. Verify the wheel and `.so` SHA-256 values published with the GitHub release.

The wheel is distributed through GitHub Releases.
