# Spire Gym 1.0.0

Version 1.0.0 is the M36 final delivery; the versioned contract freeze takes
effect with it. The Standard profile covers four characters, A0–A20, Acts 1–4
and the Heart with finite Standard content. Rust remains the single
authoritative simulator; Python and Gymnasium expose transport facades.
Training and models remain consumer-owned.

## Acceptance evidence

- Native, source-grounded, supplied Heart acceptance for four characters at A0
  and A20. The test supplies HP/max HP 900 and all three keys, and a test-only
  hook hits every enemy down to 1 HP at each combat decision. The routes
  exercise creation, Neow, map routing, events, shops, rewards, keys, the Act 3
  ending, Act 4 and terminal settlement, not real combat difficulty; each route
  is supplied, not a policy win. They are checked with replay, deterministic
  construction, semantic pins and a batch twin. Full scope and limits are in the
  [Standard Run API](https://github.com/klottick/spire-gym/blob/v1.0.0/docs/standard-run-api.md#from-start-heart-acceptance-m36).
- An ignored supplied A0–A20 sweep completed 84/84 after a test-only wound-hook
  correction. This is diagnostic evidence, not normal reach.
- Rust and Python examples, the A20 diagnostic harness, native frozen identities
  and replay digests, and Python API-name checks are described in the
  [M36 profile](https://github.com/klottick/spire-gym/blob/v1.0.0/docs/milestones/m36-final-delivery.md).
- Python artifact delivery is established by the post-merge extension build,
  whose identity is published with this release. A source-level test or the M35
  build does not substitute for that source match.

## Freeze and consumer update

The freeze covers the Standard family, card metadata, build identity fields,
the batching contract, Python public names and the M9/M10/Gym66/combat-v1
consumer surfaces. Gameplay bug fixes remain global and require affected rules
ID bumps, replay and Heart re-pins, and a changelog entry. Old records fail
closed on an identity change. Read the complete
[freeze and change protocol](https://github.com/klottick/spire-gym/blob/v1.0.0/docs/delivery.md#freeze-and-change-protocol).

Consumers should:

1. Import the extension from the intended environment and record
   `_native.__file__` and `_native.build_info()`.
2. Match `features`, `profile`, `dirty`, `source_digest` and `file_digest` to
   the values published with this release.
3. Verify the wheel and `.so` SHA-256 values and descriptor fingerprints, then
   update consumer pins.
4. Re-pin card metadata from the older `b60b66…` value to `effbb810…`.
   spire-learn's existing Gym pin is `afb51f5f`; it does not yet consume the
   Standard Run API.

The wheel and `.so` SHA-256 values and the final `source_digest` are published
with this release, not in this file. There is no PyPI release.

## Limits

The Heart routes are supplied and do not establish ordinary-start reach,
combat difficulty or policy strength. No original-runtime fidelity or source
RNG/seed parity is claimed. Random actions often end in Act 1; late game is
covered by supplied routes. Performance and memory diagnostics have no
thresholds, and measured maxima are not guarantees. See
[delivery limits](https://github.com/klottick/spire-gym/blob/v1.0.0/docs/delivery.md#known-limits-by-surface)
and the [performance record](https://github.com/klottick/spire-gym/blob/v1.0.0/docs/performance.md).
