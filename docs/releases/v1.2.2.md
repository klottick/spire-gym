# Spire Gym 1.2.2

Version 1.2.2 completes the engine-bound work started in 1.2.1 (PR #124).
It also fixes large Slow-scaled hits from FTL and pending Block accumulation
for Self-Forming Clay.

## Gameplay fixes

- **FTL.** The card applies its captured Slow-scaled damage even when it
  exceeds 30,012 and the card has already left the in-play slot.
- **Self-Forming Clay.** Each positive HP-loss event adds 3 pending Block.
  The pending total can exceed 999. The next-turn payout still caps live
  Block at 999.

## Typed engine bounds

Every remaining engine limit reachable through legal play now uses the
existing value-only bound report. It gives the counter, applicable limit
and attempted value, plus the power ID for power limits. Python exposes
these values on applicable `RunFaultError` exceptions, through
`fault_cause()`, and in batch slot and single or bulk PublicSearch fault
reports.

Cards in hand and held potions remain offered when they meet the normal
cost and targeting requirements. If their effect crosses a numeric limit,
dispatch reports the bound. A staged purchase preserves the original gold
and inventory. Outside combat, Fruit Juice stays in inventory if it hits
the maximum HP bound. A committed fault preserves work already completed.
For example, a card reward stays in the deck if Ceramic Fish's subsequent
gold grant hits the gold bound. The existing `committed` flag identifies
whether the action committed.

The new reports cover the following counters. The four counters introduced
in 1.2.1 remain documented in the [engine bounds contract](../standard-run-api.md#engine-bounds).
See also [batch fault reports](../batching.md#engine-bound-faults).

| Counter | Boundary |
|---|---|
| `doppelganger_x`, `malaise_x` | 999, including upgrade and Chemical X |
| `power_amount` | 999 on narrow positive stacks, −999 for negative Dexterity, or the relevant signed 32-bit endpoint on arithmetic overflow. The report gives the power ID. |
| `specimen_poison_transfer` | 9,999, the captured transfer amount |
| `maximum_hp`, `heal_amount`, `permanent_cards` | 999 |
| `permanent_card_identity` | 18,446,744,073,709,551,615 for the allocator cursor |
| `gold`, `damage_events`, `frost_channeled`, `lightning_channeled`, `card_upgrades` | 4,294,967,295 |
| `card_damage_base` | 0–3,003 for ordinary card base damage, or 2,147,483,647 for signed arithmetic |
| `card_combined_damage`, `card_block_base` | 10,004 and 1,007 respectively |
| `modified_damage` | 30,012 on the ordinary pipeline, or 2,147,483,647 on the signed stance pipeline |
| `modified_block` | 2,147,483,647 on the signed Watcher pipeline |
| `combat_turn`, `discarded_this_turn`, `deva_energy_gain`, `mantra_amount`, `mantra_gained`, `catalyst_poison_amount`, `snecko_skull_poison_amount`, `rampage_damage`, `windmill_strike_damage`, `perseverance_block` | 2,147,483,647 |
| `masterful_stab_combat_cost`, `masterful_stab_turn_cost`, `self_forming_clay_block`, `champ_selected_turn` | 2,147,483,647 |
| `maw_selected_turn` | 2,147,483,646 |
| `dispatch_effects` | 99,999 executable effects per dispatch. The guard retains attempted ordinal 100,000. |

at both release steps.

stored records. Combat-v1 uses its separate legacy setup and has no rules ID.

The frozen fingerprints, replay digests and Heart pins match 1.2.1.
Observation, action and descriptor layouts, Python API names and
`build_info()` keys stay the same. The version bump changes build digest
inputs, so extension builds have new `source_digest` and `file_digest` values.

## Verification

The post-merge extension build at `3c06840` reproduced the same 60 known
failures in the full `tests/python` suite. All were in
`tests/python/combat/test_rust_differential.py`. Frozen fingerprints and
replay digests matched the existing pins. These results apply to that build.

## Verify a wheel

1. Import the extension from the target environment and record
   `spire_lab._native.__file__` and `spire_lab._native.build_info()`.
2. Check that `dirty` is `false`, `features` is `["spire-python/extension"]` and
   `profile` is `release`. Match `source_digest` and `file_digest` to the
   values published with the release.
3. Verify the wheel and `.so` SHA-256 values published with the GitHub release.

The wheel is distributed through GitHub Releases.

## Known differences and limits

- **Omniscience.** The original appends both selected-card plays behind
  waiting cards. The engine puts each play ahead of waiting cards and
  schedules the second after an eligibility check. This can change play
  order when other cards are queued, such as during Distilled Chaos.
- **Storm.** The original queues Lightning before the played Power’s cleanup.
  The engine can finish the Power before channeling Lightning.
- **PublicRoot refusals.** Public roots and branches still refuse draw
  knowledge beyond supported exact cases, hidden intents from Runic Dome,
  randomly targeted autoplay and its repeats (Havoc, Mayhem, Distilled Chaos
  and Omniscience), and picks among identical draw-pile copies in cases
  involving two-pick Seek+, Frozen Eye, non-exchangeable copies or mixed
  published copies.

Earlier limits remain documented in the [1.2.0 release notes](v1.2.0.md) and
[delivery limits](../delivery.md#7-known-limits-by-surface).
