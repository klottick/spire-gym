# M34 Full-run API: Standard session, records, exact checkpoints

Status: M34a, M34b and M34c merged as PR96, PR97 and PR98 (`d657294`). The merge state does not by itself upgrade this finite profile’s acceptance evidence.

M34 adds a native and Python transport contract for Standard full runs across Ironclad, Silent, Defect and Watcher, Ascension 0–20, Acts 1–4 and the Heart. It provides a complete public decision view, explicit creation, seeded sessions, records, reward items, terminal and fault distinctions, exact checkpoints, forks and replay to a recorded decision. It makes no strategy or win claim and has no original-runtime validation. M34s (PR99–101) and M35 (PR102) are integrated; M36 records final delivery and the versioned contract freeze.

## Profile

### M34a — public view completeness

M34a normalized the Standard intent census into 197 rows keyed by `(EnemyId, move)`, covering the source intent categories and ascension conditions. The public enemy view exposes the category and the selected move's stored hit count; the Heart's live Invincible cap comes from the engine. Captured encoders, including their `intent_hits` table and 300 Heart-cap literal, were left unchanged.

The event display census added Standard-only `room_params` for displayed event values and Treasure chest size. Its final parameter-semantics table has 92 entries. The bottled-card marker is public. The v1 choice mapper now returns an input error for kinds it cannot name instead of mapping them to padding ID 0. These changes are documented in the M34a evidence and frozen encoder checks; they do not claim original-runtime validation.

### M34b — Standard session

The `Standard` profile supports four characters at A0–A20. `StandardCreation` carries full or short Neow, seen bosses by act, and the stored Note card with its upgrades. Defaults use the experienced creation profile. The environment spec publishes creation but excludes seed and RNG state. Creation validation rejects invalid input before construction.

The descriptor is built from the append-only `standard-vocab-v1` manifest. Under the r1 rule, its M34b power and intent families are frozen v1 prefixes; later shared identities append to the end of those Standard families. The schema is `spire-gym-standard-run-observation-v1`. Preset `standard-default-v1` capacities are: map nodes 107, map edges 742, permanent cards 1024, combat cards 1024, enemies 12, powers 2048, relics 256, potions 16, offers 512, selection 1024, orbs 10 and actions 2048. Descriptor domains cover the engine bounds, including declared unknown references. The final M34b Standard fingerprint is `efbc1253544a80c5c4a5b3a63cb8169a215229aaffa4ac2af5402252e195311a`.

Standard actions include named room-choice kinds and combat `discard_potion`. The reward ledger itemizes floor entries, keys, Heart victory and terminal losses; item values sum to the transition reward. Death, Heart victory, EmptyDeck and Act3NoKeys remain distinct terminal reasons; Escaped continues, `truncated` is false, and a delivery fault freezes the session instead of becoming a loss or retry. Seeded reset is deterministic; reset without a seed advances the ordinal, partitioning changes RNG, reads do not consume it, and creation remains independent across resets.

Standard records round-trip creation and replay semantically. The descriptor and observations publish only player-known information: the seed, RNG and cursor stay private; unrevealed card-reward children and event captures stay hidden; the second A20 Act 3 boss is not named before its room. Fuzz specifications cover four characters at A0, A10 and A20. The M34b extension lane reported 306 Python tests passing and all seven captured fingerprints unchanged.

### M34c — exact checkpoints and replay to a decision

An `ExactCheckpoint` is an opaque, in-memory deep copy of session state, configuration, creation, seed and ordinal, published boundary, action table and record prefix. It has no accessor, `Clone`, `PartialEq` or `Hash`; its debug output is redacted. Taking one requires a reset, usable session and does not change the live trajectory; a terminal boundary is allowed. Restore requires an unfrozen session with matching profile and configuration, republishes the saved observation under a new token, and makes earlier tokens stale. Fork creates an independent session and token from the checkpoint, including when the source has frozen or closed. Checkpoints are not portable; records are the portable form.

`RunSession::from_record(record, steps, capacities)` validates record identity, creates a session from its config, seed and ordinal, then steps through the requested prefix using normal action, publication, reward, terminal and fault checks. A prefix past the record end is rejected. A recorded fault that recurs (core, capacity or reward-item) is reproduced; a transport or batch delivery fault, which cannot recur, does not stop the prefix, as in `replay_run`. The resulting record contains that prefix under the requested capacities.

Python source adds `ExactCheckpoint` and `NativeRunSession.{decision, exact_checkpoint, exact_restore, exact_fork, from_record}`. The base `RunEnv` has the corresponding methods and `from_record`; access them through `env.unwrapped`. `ExactCheckpoint` is unpicklable, has a redacted repr and identity equality. On the built extension (M34c lane P, c2), the Python suite passed 314 tests, with imports resolved from the snapshot copy, and the example ran for four characters × {A0, A20}.

Core reserves the HMAC domain `spire-lab-research-rng-v1` and tests that it is disjoint from gameplay labels; it provides no draw API. M34s adds those draws. On supplied late-Act-3 routes at the first Act 3 boss, using release builds and medians of 31 samples, checkpoint retained heap was about 0.85–0.88 MB; take took about 27–33 µs, fork 26–32 µs and restore 54–110 µs across four characters × {A0, A20}. The ignored cost test is a measurement, not a gate. For public A0 random rollouts of 59–105 steps, `from_record` cost about 151–182 µs per accepted step because it publishes and encodes each step; `replay_run` cost about 77–105 µs per step.

See the [Standard Run API contract](../standard-run-api.md) for the consumer contract.

### Global fixes and disclosed rulings

- M34a evaluates intent category and hits from the selected enemy move and its engine-owned memory; this avoids changing individual move selectors. Heart, Spear, Byrd and Maw hit counts use shared engine helpers, and Book of Stabbing uses its stored stab count. Recorded in `m34a/task0-v1.md` and `m34a/progress.md`.
- M34a's `exploder_explode` row publishes no hits because the move is UNKNOWN; its 30 Thorns belongs to ExplosivePower. Five registered intent names have no producer: stun, lag_attack, sentry_bolt, sentry_beam and charge_up. Recorded in `m34a/progress.md`.
- The event census publishes Scrap Ooze's displayed 105% unclamped, omits Colosseum's flavor-only 4200, and does not model Knowing Skull's no-decision introductory screen. Constant identities such as Regret, Pain, Warped Tongs and Golden Idol belong in descriptor semantics, not per-step columns. Recorded in `m34a/census-corrections-v2.md` and `m34a/plan-amendments-v1.md`.
- Final census corrections add Face Trader Touch damage and gold and Cursed Tome Stop's 3 HP loss; the 92-row parameter semantics table includes these displayed quantities. Recorded in `m34a/census-corrections-v2.md` and `m34a-final-review-v1/recheck-v1.md`.
- M34a added a comparison projection that removes only the new view fields from frozen Debug receipts. M21–M24 receipt writers and readers use the same projection; M15 and M20 outputs have no recorded pre-M34a comparison. Recorded in `m34a/progress.md` and `m34a/verifier-rulings-v1.md`.
- M34b publishes present enemies only, with a capacity of 12. If a retired enemy still owns a Stasis card during a pending selection, the card remains visible with unknown owner reference `−1` and known flag 0; captured profiles keep strict lookup. Recorded in `m34b/task0-v1.md` and `m34b-final-review-v1/recheck-v1.md`.
- M34b's descriptor constants include Joust's 50-gold bet and 100/250-gold winnings, Tomb's 222-gold gain or all-gold payment, and the no-number ruling for Falling, Upgrade Shrine, Purifier and Ancient Writing. Recorded in `m34b/task0-v1.md` and `m34b/progress.md`.
- M34b records a committed reward-sum `DeliveryFault` step so replay can reproduce it; Standard record import rejects unknown keys at every checked shape. Recorded in `m34b-final-review-v1/recheck-v1.md`.
- M34b's supplied Heart frontier uses 900 HP, keys and constructed resolver-applied lethal hits; it is a test fixture, not a normal-start traversal. A 30,000 HP fixture was rejected because the engine's maximum is 999. Recorded in `m34b/progress.md` and the final review.
- M34b leaves the frozen M25 verb-12 alias unchanged (`choose_stance` and generated `ChooseCardOffer`, distinguished by `source_group`); Standard has distinct named verbs. Its test oracle for `context.act` is 255 because that field is `u8`. Recorded in `m34b/progress.md`.
- M34b keeps the standalone `m34-diagnostics` feature out of default-build feature unification, restores the M28 default-build gate, and applies the M21–M25 stance descriptor finalization and missing card domains to Standard. Recorded in `m34b/progress.md`.
- The Python `boss_history` default remains `None` with unchanged behavior. M34b review also records that semantic replay does not bind config edits that change neither legality nor reward. Recorded in `m34b/progress.md`, `m34b-final-review-v1/review-v1.md` and `m34b-final-review-v1/recheck-v1.md`.

## Limits and outs

Design §9 leaves these items out of M34:

- M34s (spire-dxo.71): public-information resampling and branching, branch limits/counters, synthetic setups, Gym66 and standalone tactical starts, and the Standard combat sidecar. M34 carries the exact-world reproduction half for spire-831 and the exact-fork half for spire-2o7. `exact_*` names are reserved for exact-world tools; M34s public-information operations use distinct names.
- M35: batching, vector environments, autoreset, partial reset and final observations.
- M36: throughput and memory gates and packaging.
- Also out: checkpoint serialization, changes to captured/policy-v3/Gym66 observations, retiring captured profiles, and the spire-learn native-pin discrepancy (consumer-side).

Semantic replay does not bind config values that do not affect legality or rewards, as documented in the M34b review. Checkpoints are in-memory only; records are the portable representation. A checkpoint carries a record prefix, and so is reproducible from the start, only when its session was created with `record_replay=True`. Exact checkpoints expose hidden world state and are privileged reproduction tools, not planning input. M34 reports no strategy strength, normal-start Heart reach from its supplied fixtures, or original-runtime validation. M34c's suites, fuzz gate, traversal, frozen replay and lane P passed (`m34c/c1-checks/results.md`, `m34c/c2-checks/`). Its independent final review is still to come.
