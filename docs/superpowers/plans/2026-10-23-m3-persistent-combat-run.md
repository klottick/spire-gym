> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native single-owner implementation. Steps use checkbox (`- [ ]`) syntax for tracking. One independent milestone review follows integration, not each task/card.

**Goal:** Run two consecutive real Ironclad A0 fights through one persistent native run owner, preserving permanent resources/identities and committing entry, settlement and death exactly once.

**Architecture:** Add a thin run/combat bridge around the existing enemy setup, `Combat` resolver and lossless item entry/exit. Keep the permanent deck canonical in `RunState`, transfer inventory into the active combat, project active resources from that owner, and automatically settle actual outcomes before returning to the caller. A named authored-run constructor bypasses unimplemented Neow for this checkpoint without pretending normal starts or room progression work.

**Tech Stack:** Existing Rust workspace, locked/offline dependencies and standard-library example argument parsing. No installs, Python extension rebuild, new dependencies, second simulator or verification framework.

**Spec:** User-approved `docs/superpowers/specs/2026-10-22-narrow-gym-milestones-design.md`, M3. Accepted predecessors: `docs/milestones/{m1-combat,m2-combat}.md`. Planning: `spire-dxo.25.1`; outcome: `spire-dxo.25`.

## Review Focus

1. Entry rejection versus post-transfer failure: rejected setup consumes no inventory, visit or RNG; an accepted startup fault retains the actual combat/advanced state and cannot replay entry.
2. Last-hit and exhausted ownership: include terminal `in_play` and every pile when validating permanent identities; neither exhausted originals nor generated Anger copies may corrupt the permanent deck.
3. Settlement ordering: combat already ran Burning Blood; run settlement must not heal again, refund potion slots, reset max HP or resurrect death. Accepted settlement faults retain their actual terminal combat.
4. Public/action ownership: active HP/items come from combat, not stale/empty run fields; pure reads and rejected actions do not advance RNG, and Neow/map/deck actions cannot mutate an active fight.
5. Consecutive fight identity: fresh local powers/cards/first-turn relic latches, different semantic combat visits, preserved permanent upgrades/gold/counters and no fabricated run victory after two fights or caller-budget exhaustion.
