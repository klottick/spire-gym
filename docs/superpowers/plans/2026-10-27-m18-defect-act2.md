# M18 Defect through Act2 Implementation Plan

> **For agentic workers:** Implementation is held until the primary user approves the reviewed design/plan and root binds accepted M16/M17/required shared source. Follow the execution method authorized in that session. Use focused TDD and one fresh independent final milestone review; this plan does not authorize per-task review swarms or product work now.

**Goal:** Deliver a finite canonical normal-start Defect A0 Acts1–2 native profile with actual Act2 boss alternatives, real rewards and a healthy Act3Ready boundary.

**Architecture:** Extend shared Run/character/combat/content owners, compose accepted M17's Act1 prefix with existing Act2 rooms, and extend the same observation/session/replay/batch dispatch. Keep finite capture data separate from shared rules; no parallel Defect simulator or persistence journal.

**Tech Stack:** Rust `spire-core` and `spire-env`, locked offline Cargo. Native-only; no Python extension refresh.

**Spec:** [M18 design](../specs/2026-10-27-m18-defect-act2-design.md). All content rows, source qualifications, dependencies, fixed cases and endpoint semantics there are part of this plan.

## Global Constraints

- M18 is Defect A0 from canonical normal start through actual Act2 and Act3Ready (Act3/floor34); no Act3 decision is accepted.
- Keep combat-v1, policy-v3, old profile IDs, boss-history spellings, fingerprints and accepted endpoints frozen, including M17's future accepted Act2Ready prefix.
- The finite capture is exactly the design's 29 permanent kinds, four generated status kinds, 14 relic kinds and five potion kinds; no full-pool, standard-rarity or M20 completeness claim.
- `RunSessionConfig` keeps one `boss_history` field. M18 adds a typed composite using existing Act1/Act2 target enums before Run construction.
- Use shared `A0_ENCOUNTER_SETUPS`, Run entry/settlement, character-owned admission/value handlers and room/reward/shop/rest/transition owners. No M18 orb/card scheduler, master deck, mutation history or theft journal.
- Every source symbol added below is a proposal. M16/M17 APIs do not exist at planning baseline e5b07da; accepted-source reconciliation is a hard implementation dependency, not authority to implement those milestones.
- Freeze and hash the public-only caller and six fixed cases before outcome runs. Retain every outcome; no post-outcome tuning, seed search, later-state injection or automatic transfer of prior coverage amendments.
- Actual entry plus matching combat record establishes boss coverage. At least one canonical normal-start Act2 boss Victory through real rewards/chest to Act3Ready is required; supplied diagnostics do not replace that gate. Death, budget, fault, stock exhaustion and cutoff stay distinct.
- No current build/test/install/commit/PR/cleanup authority; future execution/publication authority comes only from the primary session. No blanket staging or historical workspace-green claims.

## Review Focus

1. **Unaccepted/mismatched upstream and history:** M16/M17 source identity and M18 profile/character/A0/history must be bound before creation/reset; all nine valid boss pairs round-trip, malformed or cross-profile histories reject without mutation. Task0 receipt; Task4 `m18_config_history_is_typed_and_profile_bound`.
2. **Dynamic Defect public state:** Dark payloads, sparse ten slots, mutable card values, Confused, Stasis, summons and generated statuses must encode truthfully without raw IDs or hidden future state; foreign content/capacity overflow fails closed. Task2 source interactions; Task4 `m18_reachable_values_encode_and_foreign_or_hidden_state_fails_closed`.
3. **Cross-act finite stock custody:** Act2 visits/cursors restart, owned relics skip, declined published stock stays consumed, full-belt claim survives discard, and depletion never refills or advances the failing lookup. Task1 `m18_act2_finite_offers_preserve_local_cursors_and_claim_custody`.
4. **Accepted action/child and persistent-card fault:** GA mutation survives actual Stasis/death/accepted-prefix fault once; boss child/heal/reward/map commits do not repeat on retry. Task2 `m18_genetic_algorithm_stasis_and_fault_keep_permanent_identity`; Task1 `m18_boss_children_transition_and_fault_are_single_commit`.
5. **Outcome and boundary confusion:** Every fixed run remains evidence even when it dies early; real boss entry differs from icon, budgets0/1 are not Death, and Act3Ready is nonterminal/resettable/zero-action with no bonus or Act3 action. Task3 fixed matrix and controls; Task4 cutoff test; Task5 replay/batch agreement.
