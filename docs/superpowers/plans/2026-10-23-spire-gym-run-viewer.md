# Spire Gym Run Viewer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export actual native combat replays and accepted run prefixes as an offline, read-only action slideshow, preserving the approved whole-run tactical layout.

**Architecture:** Add a narrow, opt-in observation seam to the existing Rust resolver and replay path, then adapt public native values into a separately versioned streaming display protocol. An optional `spire-report` crate owns capture, safe HTML/image packaging and static viewer resources; the browser never calls the simulator. Existing native run/content owners retain their mechanics and milestone boundaries.

**Tech Stack:** Rust 1.99.0 repository toolchain; existing `spire-core`, `spire-env`, serde and serde_json; Python 3 standard library for explicit artwork preparation; plain HTML/CSS/JavaScript; existing Chromium/Playwright development tooling when available. No new runtime framework or third-party dependency installation is authorized.

**Spec:** `docs/superpowers/specs/2026-10-23-spire-gym-run-viewer-design.md` — approved by the user on 2026-10-23.

## Global Constraints

- One slide per actual chosen action, with automatic consequences grouped with it.
- Static, utilitarian presentation: no animation, autoplay, gameplay controls, alternative-action exploration or invented decision rationale.
- Original StS1 artwork when explicitly supplied; names and numbers when missing. No replacement illustrations, committed proprietary images or runtime downloads.
- Export one self-contained HTML document that opens with `file://` offline.
- Store large IDs as strings. Do not invent unavailable values or treat `null` as zero/empty.
- Exclude RNG roots/cursors, unseen draw order, future AI selections, hidden room contents and future loot.
- Ordinary stepping with recording off must serialize no state, allocate no trace data or change existing output.
- A captured prefix must say it is a prefix. Capture completion is separate from gameplay outcome.
- The first real end-to-end adapter is the existing supplied-entry combat replay; the same report contract then consumes the accepted run-prefix producer.
- Do not relax reference `trace-v1`, import private snapshots/reproduction jobs, add gameplay mechanics or promote original-runtime fidelity.
- Do not edit `docs/research/relics/`, card-reference work, other workers' workspaces, milestone plans or training code.
- Any Luna assistant/reviewer gets a separate native-created worktree, an explicitly materialized agreed public source baseline/candidate, and a unique `CARGO_TARGET_DIR`. Native creation alone may start at obsolete main. Never dispatch into the controller's live checkout, copy ignored/private evidence/artwork, or overlap shared-engine edits.
- Reuse the repository's focused checks and report build time separately. Diagnose warm M1-focused commands above5s or warm workspace commands above30s; these are investigation thresholds, never flaky timing assertions or permission to weaken tests.
- No commits, pushes, installs or changes to another workspace are implied by this plan. Checkpoint steps below record intended commit boundaries/messages; execute `git commit` only with separate explicit authority.

## Review Focus

- A queued card opens a selection and later resolves under another action: preserve its parent/card identity and effect ownership without duplicate execution. Tasks 2, 4 and 8 pin this.
- A lethal action automatically settles combat before `Run::step` returns: retain the defeated roster and gross HP effects, while using once-only settled run resources. Tasks 2 and 4 pin this.
- A source yields no candidates at a captured prefix boundary, or collection stops at a budget: do not call either victory, loss or full-run completion. Tasks 1, 6 and 9 pin this.
- A public target table contains replaced actors/new summons and repeated card names: resolve native identities, never current array indexes or display-name guesses. Tasks 2, 4 and 8 pin this.
- A recorder/output failure follows an accepted native action: retain evidence, distinguish pre-call versus post-call failure, never retry the action or fault a healthy live pool. Tasks 1, 4, 5 and 6 pin this.

### Wire decisions

- Header: `{record:"header",schemaId:"spire-report-v1",schemaVersion:1,source:{kind,profile,producerRevision,contentId,evidenceGrade},run:{character,ascension,seed:{encoding,value},caller}}`. Known source kinds are `combat_episode`, `run_prefix`, `run`, `authored_fixture`. Seed value is text; roots/cursors are absent.
- Frame: `{record:"frame",frame:{id,previousFrameId,kind,act,floor,combatId,turn,action,beforeScreen,state,effects,combatFinal,stateValidity}}`. IDs/references are strings, starting at `"0"`; consecutive frames reference the previous ID. `combatFinal` preserves a terminal public roster across automatic run settlement. `stateValidity` is `settled` or `last_known`.
- Kinds: `initial`, `action`, `boundary`, `fault`, `end`. Only accepted actions use `action`; rejected actions add no frame. Fault frames may carry a separately labelled attempted action, not a claim that it settled.
- Footer: `{record:"footer",capture:{status,reason},game:{outcome,boundary}}`. Capture statuses: `complete`, `unfinished`, `abandoned`, `faulted`, `interrupted`. Game outcomes: `null`, `combat_victory`, `death`, `heart_victory`, `empty_deck`, `act3_no_keys`; game boundary is nullable text such as `act2_prefix_complete`. Never derive it from an empty menu or the capture status.
- State: `{screen,player,inventory,map,combat,terminal}`; `terminal` preserves the nullable native run terminal. Screen: `{kind,name,options,selection}`. Option: `{key,label,status,data}`; `status` preserves offered/claimed/skipped/disabled. Action: `{type,description,source,targets,card,optionKey,preActionOffer,parentActionId}`.
- `player` has authoritative `hp,maxHp,gold,block,energy,statuses`; unavailable legacy run values are null. `inventory` has `deck,relics,potions,keys`; an unavailable inventory is null, not an assertion of no owned items. `combat` has `id,turn,enemies,hand,piles,selection,character,stasis,lastPlayedCard,outcome`; `outcome` preserves nullable native combat Victory/Death distinctly from run terminal. `piles.draw` is `{count,knownCards:null,orderKnown:false}`, while public discard/exhaust are card arrays. Do not expose hidden draw identities to populate `knownCards`.
- Card: `{ref,origin,cardId,name,upgrades,baseCost,currentCost,freeToPlay,assetKey}`. Unknown costs/free flags are null, not calculated from rules in JavaScript. Permanent origin and combat reference remain separate.
- Enemy: `{ref,logicalSlot,monsterId,name,hp,maxHp,block,statuses,lifeState,intent,assetKey}`; intent includes nullable `damagePerHit`/`hitCount`. Unknown hit counts are not inferred from AI names or the example policy's threat heuristic.
- Catalog additions are `{record:"catalog",entries:{key:definition}}`, immutable and written before first use. Asset keys use native stable IDs, e.g. `card/strike`, `card/bash`, not the other simulator's enum names.
- Effects have numeric bounded `sequence`, string `kind`, nullable source/target reference, text `description`, and appropriate observed `before,after,incoming,absorbedBlock,hpLost,overkill,amount,field,resolvedMove` fields. Convert native snake_case fields to this wire vocabulary in one adapter; never serialize private native structures as the effect payload.
- Parsed document is `{schemaId,schemaVersion,source,run,catalog,frames,capture,game,warnings,assets}`. `assets` is `{byKey,blobs,sources,attribution}`, with exact-byte-deduplicated data URLs.
