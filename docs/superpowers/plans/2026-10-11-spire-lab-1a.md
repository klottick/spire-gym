# Spire Lab 1a Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver validated A0 starter Ironclad combat against Cultist/Jaw Worm, a safe native batch interface, and a reproducible first PPO learning comparison.

**Architecture:** Owned Rust combat state and typed effects feed one public observation encoder and a synchronous native pool. A thin owned-array Python boundary supports a small candidate-scoring PPO learner. Windows reference-runtime fixtures validate the supported mechanics before substantive training.

**Tech Stack:** Rust/Cargo, serde/serde_json, SHA-256 fingerprints, Rayon, PyO3/rust-numpy, maturin, Python/uv, NumPy, PyTorch, pytest; Java/Gradle and ModTheSpire for the Windows capture mod.

**Spec:** `docs/superpowers/specs/2026-10-11-spire-lab-ml-first-design.md` (approved 2026-10-11).

## Global Constraints

- "Primary optimization target: held-out playing strength gained per wall-clock hour, subject to game-correct simulation and player-visible information."
- "The core has no Python, tensor-library, renderer, or training dependency."
- "No mutable game globals."
- "Implement only phases/hooks required by current supported content; do not build a generic plugin engine."
- "Invalid actions leave state unchanged."
- "Initial automatic-work guard: 100,000 resolved effects per external step."
- "Never substitute Rust's default RNG for game transitions."
- "Do not invent independent streams where the game shares one."
- "No seed, RNG state, unseen draw order, unpublished enemy rolls, internal UUIDs, scenario IDs, or environment IDs as model features."
- "Initial binding outputs are safely owned numeric arrays copied per batch."
- "No JSON, card-level Python objects, state clones, or debug formatting in rollouts."
- "Phase 1a preallocates `C=32`, `K=0`, `S=0`."
- "Never truncate data, drop legal actions, or silently resample."
- "Baseline reward is +1 for resolved victory, -1 for death, zero otherwise; gamma is 1 for finite-combat returns."
- Defaults: slots/workers 256/8; rollout length 128; PPO epochs/minibatch 4/2,048; learning rate/clip 3e-4/0.2; GAE lambda/value coefficient 0.95/0.5; entropy/gradient cap 0.01/0.5.
- Training seeds 7, 17, 29; administrative limits 100 turns or 5,000 policy decisions; per-seed budget 2 hours or 20 million decisions, whichever comes first, checked between updates.
- "Tiny optimizer smoke tests may run beforehand but cannot be presented as validated learning results."
- "Any internal error invalidates the evaluation run rather than being dropped."
- "Keep game binaries, assets and decompiled game source outside the repo."
- Linux development/training, Windows reference game; no live network connection required. Pin resolved toolchains/lockfiles at execution; the spec sets no numerical version floor.
- Only Strike/Defend/Bash in base/upgraded forms, Cultist/Jaw Worm, Burning Blood, Ironclad A0; no potion mechanics, map, events, other content, or Heart implementation in this plan.

## Review Focus

1. Unavailable or changed Windows reference dependencies: missing/changed build IDs must block validated promotion, not trigger synthetic replacements (Tasks 2, 7).
2. Corrupt/oversized traces or snapshots: reject unknown schemas, lossy RNG encodings, duplicate identities and invalid boundaries before mutating state (Tasks 2, 4, 7).
3. Wrong-shaped, stale or concurrent batch calls: reject before mutation; a runtime failure faults the pool rather than returning partial success (Tasks 9, 10).
4. Held arrays/checkpoints across reset or restart: arrays remain unchanged; reset tokens expire; incompatible or incomplete checkpoints cannot silently resume (Tasks 10, 14).
5. Small/nondivisible minibatches, all-masked rows and time limits: no NaNs or dropped data; terminal rows skip inference and truncations bootstrap from the final state (Tasks 11, 12, 14).
